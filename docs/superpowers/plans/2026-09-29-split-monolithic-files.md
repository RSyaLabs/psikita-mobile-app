# Plan: split the three monolithic files

**Date:** 2026-09-29
**Precondition:** the working tree must be committed first, in slices, so there is a
rollback point. Do not start this plan against an uncommitted tree.
**Baseline to preserve:** `npx tsc --noEmit --incremental` returns 0 errors, and
`npx jest --ci --maxWorkers=2` reports 370 of 371 passing.

## The safety property

Every hook, component and type exported by these three files must keep the same name
and the same signature after the split. Callers must not be edited. If a split requires
changing a call site, the split boundary is wrong.

That is the check that makes this safe: after each step, the only thing that changed
should be file locations. If a diff shows a behaviour change, stop and re-read.

## Do not touch

- `src/components/ui/icon/index.tsx` and `index.web.tsx`. 1588 and 1573 lines, but
  only 5 lines are logic; the rest is per-icon boilerplate generated by Gluestack. It is
  vendored. Editing it is a mistake, and it is not a monolith.
- `src/types/api.ts`. 494 lines, and it is the contract this client believes the server
  implements. Splitting it is possible, but it invites accidental changes to what the app
  thinks is true, and no test would catch a drift there.

## Step 1 — `src/hooks/useApiQueries.ts`, 1400 lines

Largest and highest value. One file holds every server query in the app, so any change to
it produces a diff nobody can review.

1. Enumerate every export first. Write the list to a scratch file before moving anything.
2. Group the exports by the domain they already serve. The repository already has these
   domains, visible in the route groups and in the service files: patient, practitioner,
   consultation, notification, article, payment, admin, matching, prescription.
3. Create `src/hooks/queries/<domain>.ts` for each group. Move whole exports, never
   partially. Do not rename anything. Do not "tidy" a hook while moving it.
4. Replace `useApiQueries.ts` with a barrel that re-exports everything, so every existing
   import path keeps working:

   ```ts
   export * from "./queries/patient";
   export * from "./queries/consultation";
   // ...one line per domain
   ```

5. Verify before continuing:

   ```sh
   npx tsc --noEmit --incremental
   npx jest --ci --maxWorkers=2
   ```

   Both must match the baseline. A caller edit appearing in the diff means stop.

## Step 2 — `src/components/modals/AuthModals.tsx`, 914 lines

1. Enumerate the modal components it exports.
2. Split by flow, not by file size: login form, register form, forgot password.
3. Shared pieces used by more than one flow, such as the password field or the strength
   meter, move to `src/components/modals/shared/`. Only create that directory if two or
   more flows genuinely need the same piece; do not create it preemptively.
4. Keep `AuthModals.tsx` as a barrel.
5. Run the same two checks.

## Step 3 — `src/components/modals/PractitionerModals.tsx`, 960 lines

Already reduced from 1837 earlier in this work, so it is closer to acceptable than it was.
Split it only if steps 1 and 2 are done and verified.

1. Enumerate exports.
2. One file per modal, because these are already independent components.
3. Barrel, then the same two checks.

## Order and rules

- One step at a time. Do not batch them.
- Run the full gate after each step, not at the end.
- Commit after each step, so a bad split is one revert away.
- Never `git checkout` a file in this tree. Twice this session that destroyed verified
  work: the `assertCapabilityLive` tests, and an `isRecord` consolidation in `client.ts`.

## Known unrelated open item

`payment-flow.test.tsx` needs `--forceExit` because some suites render a hook and never
unmount it, leaving a TanStack `notifyManager` timeout alive. `--detectOpenHandles` points
at `node_modules/@tanstack/query-core/src/notifyManager.ts:46`.

Do not attempt to fix that by changing the Jest runner. It was measured: the whole suite
hangs under `--runInBand` too, taking 312 seconds, so runner configuration is not the
cause. The fix belongs in the tests, by unmounting or clearing the query client. Fix it
before or alongside this plan, not as part of it.
